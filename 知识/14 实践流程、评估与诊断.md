# 14 实践流程、评估与诊断

> 目标：从一个最小可信模型开始，检查“算对了没有、假设合不合适、结果能不能推广”。本节是基于前面原理整理的实践建议，不是某个现成软件的操作手册。

## 1. 先写问题，再画图

用一句话写清任务：“根据截至今天的报警预测明天报警概率”，或“回看整段运行，估计故障发生时间”。接着写出概率目标、观测截止时间、输出形式和评估标准。

再定义每个变量的含义、单位、时间粒度、可见／隐藏、取值集合或分布类型。初始状态、序列边界、动作和缺失标记也要规定。没被观测不等于可以随便赋予隐变量语义。

## 2. 先跑一个能手算的小模型

用 [[04 贯穿例子：设备状态与报警]] 的参数，确认前向算法能复现：第一次报警后故障概率约 0.470588；第二次报警前预测约 0.402941；两次报警后当前故障概率约 0.843726。

长度为 2 或 3 时，枚举所有状态路径求联合概率，与递推结果对照。这种独立计算可以发现转移矩阵方向写反、漏掉第一个发射概率、索引错位或错误归一化。大规模运行成功不等于这些细节正确。

## 3. 一个可直接读懂的过滤实现

下面只用 Python 标准库。顺序为正常、故障；$A$ 的行是旧状态、列是新状态。它是数学递推的最小展示，不含参数训练和粒子滤波。

```python
from math import log

pi = [0.9, 0.1]
A = [[0.95, 0.05], [0.20, 0.80]]
# B[状态][观测]，观测 0=不报警，1=报警
B = [[0.90, 0.10], [0.20, 0.80]]
observations = [1, 1]

posterior = pi[:]
log_likelihood = 0.0
for t, y in enumerate(observations):
    # 第一片使用初始分布，不先做一次转移
    prior = posterior if t == 0 else [
        sum(posterior[i] * A[i][j] for i in range(2))
        for j in range(2)
    ]
    weights = [prior[j] * B[j][y] for j in range(2)]
    evidence = sum(weights)
    if evidence <= 0:
        raise ValueError("当前观测在模型中概率为零")
    posterior = [w / evidence for w in weights]
    log_likelihood += log(evidence)
    print(t + 1, "故障后验", round(posterior[1], 6))
```

预期两行故障后验为 `0.470588`、`0.843726`。序列似然是 0.06495，对数似然约 -2.734138。

先能解释每一行对应“求和、乘似然、归一化”中的哪一步，再尝试改参数。能运行代码与自己掌握递推是两件需要分别确认的事。

## 4. 时间数据怎样划分

实时预测任务通常按时间先后划分训练、验证、测试。来自同一条轨迹的相邻窗口高度相关，随机混洗窗口可能把几乎相同的片段分到两侧；预测窗口重叠时，还要根据目标跨度设置合理的隔离。

如果目标是泛化到新设备，应按设备划分或另设新设备测试。若部署时允许使用测试期开始之前的历史，初始化可用这些历史做过滤；是否允许要事先说明，不能使用测试期未来观测。

缺失处理、离散化阈值、标准化和模型选择都只能利用训练数据拟合，验证集用于选择方案，测试集留到最终检查。EM 对训练序列做平滑本身合法，跨到验证／测试信息才构成泄漏。

## 5. 评估什么

| 目标 | 可用指标或检查 | 限制 |
|---|---|---|
| 预测观测分布 | 平均负对数预测似然 | 必须比较同样的变量、数据与观测表示 |
| 已有真实状态标签 | 分类错误、混淆矩阵、Brier score、校准 | 状态类别不平衡时准确率可能误导 |
| 连续状态估计 | MAE/RMSE、区间覆盖与宽度 | 均值准不代表不确定性准 |
| 结构发现 | 仿真真图对照、边稳定性、预测增益 | 稳定也不能单独证明因果 |
| 推断算法近似质量 | 与小模型精确后验比较、运行成本 | 同时记录误差与速度，不能只报速度 |

没有真实状态标签时，不能直接声称“故障识别准确率高”。可以评价观测预测、用人工核查或少量标签作外部验证，并检查模型生成的序列是否具有合理的频率、持续时间和自相关。

## 6. 残差与模型检查

对连续 Kalman 模型，检查 innovation 的均值、协方差与时序相关：若持续有偏或明显相关，可能遗漏动态结构或噪声假设不合适。对离散观测，可比较预测概率与实际频率，并检查特定工况下是否系统性误报。

仿真数据有价值：从已知 DBN 生成数据，再学习或推断，检查在样本量增加时是否改善。仿真成功只能证明在相应设定下有效，不能替代真实数据外部验证。

## 7. 常见现象与优先排查方向

| 现象 | 先检查 |
|---|---|
| 后验所有状态都变成零 | 下溢、零概率 CPD、观测编码、提议支持 |
| 训练好、测试差 | 泄漏、参数过多、工况漂移、隐状态过拟合 |
| 状态几乎不切换 | 转移初始化、先验、时间粒度、真实持续时间 |
| PF 看似稳定但多样性低 | 祖先塌缩、重采样频率、过程噪声、ESS 解释 |
| EM 不同初始化差别大 | 局部最优、不可识别、数据不足、状态冗余 |
| Kalman 极度自信却误差大 | $Q/R$ 低估、模型偏差、非线性、异常观测 |

## 8. 第一轮实践的完成标准

你能解释变量与假设，手算小例子并和程序对上，分清过滤与平滑，说明参数来自哪里，并指出一条模型可能失效的情况。随后再增加一个状态分量或学习环节。

无需一开始同时实现所有方法。先用小 HMM 获得可核对的基线，再选择多变量 DBN、Kalman、PF 或 EM 中与你的研究问题最相关的一条。
